# 找活手册（Work Finding · 反空转）

> 目标：主控的产出是"持续有活干的流水线"，不是单个波次的执行。管道空了，第一责任人是主控——空窗不是休息信号，是计划缺口信号；"分不出活"就是规划本职失守。
> 依据：Anthropic 多智能体研究系统（努力分级、防过度派发）+ OpenClaw HEARTBEAT.md 心跳清单与 Dreaming 模式（空闲期自找活，带阈值防造活）+ Kanban ready 队列（候选池永不满空）+ 决策备忘录文化（升级人必须带选项与建议，让人做单选）。
> SKILL.md 只留规则；本文件是扫描清单、等人事项三分法与收官协议。波次收官、等待窗口、被唤醒续轮时通读。

## 1. 职责定位

- 主控的三种产出：**任务书**（常态）、**裁决**（冲突时）、**候选池补给**（空窗时）。管道空 = 第三种产出的强制触发器。
- "无活可派"永远是一个**待验证的主张**，不是可以随手下的结论——与 `DONE` 一样需要行为证据：扫描痕迹就是它的证据。
- **找活 ≠ 造活**：每个候选必须挂得上价值源（用户目标 / 风险 / 质量债 / 可判定等待项），挂不上的删除。Anthropic 的教训同样适用：无节制找活会 spawn 出一堆低价值子会话，协调成本反噬收益。扫描的合法结果允许是"0 张新任务书"，但必须留下逐源"已核无活"的结论。
- **无新功能 = 打磨期**：新功能类候选扫完为零时，默认答案是**打磨已有功能**——边界与异常路径、性能与可观测性、UX 走查、测试补强、文档对齐、慢查询与告警盲区。功能上线只是 60 分，打磨才推向 90 分；打磨任务天然落在自主权限内（不触契约与范围），是空窗期与收尾波次的一等公民选择，不是"没活才干"的备胎。

## 2. 找活扫描（九源清单）

收官、等待窗口、被唤醒续轮时机械过一遍。每源产出一个候选，或一句"已核无活"结论入账本：

| # | 源 | 查什么 | 常见产出 |
| --- | --- | --- | --- |
| A | 需求对账 | TODO.md 验收标准逐条 × 已派任务：有没有标准没被任何任务覆盖？"明确不做"之外是否还有未展开的目标？ | 补漏任务书 |
| B | 账本 Guesses | 每个 Guess 核对过期条件：到期未证伪的升级 Facts 或删除，禁止静默留着 | 细化 / 重派 / 销账 |
| C | Known Issues | 项目记忆里的 known-issues、红线复测项；历史修复是否都带了回归测试 | 回归测试任务 |
| D | 用户等待项 | 凡标着"等用户裁决 / 等人执行"的事项，逐条过第 3 节三分法，拆准备链 | 备忘录 / runbook / 探针 |
| E | 质量债 | 集成旅程测试缺口、行数红线巡检、依赖 outdated / audit、文档漂移（README/规范文件与实现不一致） | 治理小任务 |
| F | 安全与风险 | 权限/计费/鉴权探针复测、备份可恢复性演练、回滚预案存在性核查 | 探针 / 演练任务 |
| G | 验收工具化 | 收官清单里"人手工验收"的步骤，哪些能做成脚本/探针/清单，让下次人工验收只剩最后一步 | 工具化任务 |
| H | 待细化区 | 逐条核对细化触发条件：命中了吗？触发条件本身可观测吗（谁在看、怎么看到）？远期条目要不要先做调研 spike（不改计划）？ | 细化 / spike |
| I | 经验沉淀 | 本波次踩坑是否已喂项目记忆（self-evolving 类）；新教训是否要回填所用技能 | 沉淀动作 |

过滤闸门（防造活，逐候选过三问）：

1. **值得吗**——挂得上价值源吗？挂不上 → 删，不许"反正闲着"。
2. **我有权限吗**——按分级审批：发现性小任务 / 治理类自主派；触范围、契约、不可逆的 → 出决策备忘录先问，不直接派。
3. **现在派吗**——立即派发，还是入候选池？候选池在账本里永远有一节，收官时补给，永不允许空着还没解释。

## 3. 等人 ≠ 停摆（裁决项三分法）

凡"需要人裁决 / 人执行"的事项，拆成三层，**只有第一层合法等待**：

| 层 | 内容 | 处置 |
| --- | --- | --- |
| 裁决本体 | 不可逆/破坏性动作本身；只有人能做的最终验证（真实账号、真实支付、真金白银） | 等人 |
| 准备链 | 决策备忘录（选项 A/B + 影响面 + 回滚成本 + 主控建议）、执行 runbook（精确到命令）、影响面调查（谁还在消费该资源）、可逆预备（备份 dump、预演环境、干跑） | 自主权限内，**立即派发** |
| 验证工具化 | 把人的手工步骤压缩：探针/脚本先跑，人只做最后一步并看自动收集的证据 | 立即派发 |

- 标准：人收到的问题必须是**单选题**，不是论述题，更不能是"动作权在您"式的整题外包。合规收尾形态："决策备忘录已落盘 `<路径>`，选项 A/B，建议 A，您回一个字母即开新一轮波次。"
- **先问 ≠ 空等**：升级人的同时准备链照常派发——批准的是动作，不是思考。等待期是找活扫描最好的执行窗口。
- "等人"标签豁免的只有裁决本体，不是主控的找活本职；把整项挂起而不拆准备链，就是拿等待当偷懒的理由。

## 4. 心跳清单与 Dreaming

- 每个账本目录维护一节**心跳清单**（或独立 HEARTBEAT 文件）：主干门禁绿否、worktree/分支残留、未归档会话、Guesses 到期、候选池待派、各等待项触发条件是否命中。**每次被唤醒续轮或收官，先跑一遍心跳再干活**——它同时是找活扫描的输入和"无活"结论的证据。
- **Dreaming**（借 OpenClaw 模式）：连续若干轮只产出心跳 OK、零新任务 → 启动改进型自找活：**打磨已有功能** / 治理 / 工具化 / 沉淀类小任务（第 2 节 E/F/G/I 源）。阈值启动防止忙碌期造活；Dreaming 产出同样受分级审批约束——触范围与契约的，出决策备忘录而不是直接干。

## 5. 收官协议（收官报告硬结构）

波次全部归档、无在飞子会话时，按序执行：

1. 心跳清单全过；
2. 找活扫描九源全过；
3. 候选三分：立即派发（自主权限内）/ 入候选池 / 出决策备忘录升级人；
4. 下一波次预置：锁定区任务书草稿，或候选池补给与触发器声明。

收官报告必须包含四段：

- **本轮新派**：任务书编号；0 张必须有扫描结论佐证；
- **等人项清单** × 每项准备链完成度（备忘录路径 / runbook 路径 / 已工具化程度）；
- **候选池现状**：条数 + Top 3；
- **下一波次触发器**：人回哪个字 / 命中什么条件，即开新一轮。

"无新任务可派"的合法性条件 = 九源扫描逐项留痕 + 候选全部处置（派发/入池/升级）+ 等人项准备链全部铺完。三者缺一，"无活"是偷懒不是结论。

## 6. 反面案例（通用化实录）

> 收官报告："本波次全部验收合并归档。剩余事项：①某真实环境冒烟——按裁决由用户承担；②某不可逆资源下线——待用户裁决时机；③待细化区——触发条件未命中，维持搁置。当前无在飞会话、无阻塞项，下一步动作权在用户。"

违规点逐条：

- 三个等待项各有大片可自主推进的准备链（①验收探针与测试环境预演；②资源依赖调查 + 备份 dump + 下线 runbook + 决策备忘录；③触发条件可观测性检查 + 调研 spike），一项都没拆；
- "无阻塞项"与"三项在等"自相矛盾——等待项被**分类掉了**，而不是被**转化掉了**；
- "下一步动作权在用户" = 把单选题外包成论述题；合规形态是"备忘录已备好，您选 A/B"；
- "无新任务可派"没有扫描证据，是被"等人"标签豁免了找活义务——而"等人"豁免的只有裁决本体。

## 7. 红线

- 禁止以"无新任务可派"收尾而无九源扫描留痕；零任务书合法，零扫描痕迹不合法。
- 禁止把等人裁决的事项整项挂起——裁决本体等人，准备链（备忘录 / runbook / 备份 / 探针）自主派发。
- 禁止"下一步动作权在您"式决策外包——升级人必须附选项、影响、回滚与建议，让人做单选题。
- 禁止把人的手工验收原样交付——能工具化的先工具化，人只做最后一步。
- 禁止为找活而造活：候选挂不上价值源的进不了任务书；连续空轮先走心跳与 Dreaming 阈值，不硬找。
- 禁止绕开分级审批：扫描出的活触范围/契约/不可逆 → 出决策备忘录先问，不直接派。

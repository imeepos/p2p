# 自适应计划手册（Adaptive Planning Playbook）

> 目标：计划不是一次定死的文档，而是随执行反馈持续演进的产品——但演进必须有触发器、有版本、有审批分级，不是随手改。
> 依据：Magentic-One 双循环账本（arXiv 2411.04468）+ Anthropic orchestrator-workers / evaluator-optimizer + GAO/PMBOK 滚动波规划。
> SKILL.md 只留规则；本文件是节奏、触发器与账本结构规范。制定计划时通读；每次收到子会话汇报时对照第 1–2 节执行。

## 1. 双循环节奏

**内循环（默认态）**：每个子会话汇报事件触发一次，对照任务账本 + 汇报回答**五问**，答案逐行记进度账本——不等阶段边界，每个事件都是一次裁决：

1. 该任务完成了吗？（只认验收证据，不问口头）
2. 整批在空转/重复吗？（同类问题第二次出现 = 空转信号）
3. 有前向进展吗？（合并了什么/契约推进了什么，拿盘上产物说话）
4. 下一步动作派给谁？（派发 / 打回 / 评审 / 合并 / 等待）
5. 给它的具体指令是什么？（结构化反馈，禁"再试一次"）

**外循环（重规划，触发式）**：停滞计数超阈值（同一任务打回 ≥2 轮 / 整批无合并进展）或第 2 节触发器命中时执行：

1. **反思三问**：哪里错了？执行中学到什么新事实？下轮换什么打法？
2. 更新任务账本：Facts/Guesses 校准，计划版本 +1，变更日志记一行。
3. 修订计划（在滚动波两区结构内改，见第 3 节）。
4. 必要时重置执行者上下文：换新会话重派——与修复熔断（第 4 轮换会话）共用同一机制，不另造一套。
5. 重开内循环。

## 2. 重规划触发器与标准响应

子会话的终态复盘（`task-brief.md` 汇报格式中的复盘节）是本表前三类触发器的情报源：「新事实」经你核对证据后入账本 Facts；「过度设计候选」「下一步建议」是候选不是结论，采纳与否由你裁决并记账。

| 触发器 | 判定信号 | 标准响应 | 审批级 |
| --- | --- | --- | --- |
| 顾虑裁定 | `DONE_WITH_CONCERNS` | 逐条裁定：采纳→改计划/验收口径；驳回→账本记理由 | 自主 |
| 阻塞波及 | `BLOCKED` 且其产出被下游 Consumes | 替换路径/降级/重排下游；受影响消费方的任务书全部修订重发 | 自主 |
| 实现反复 | 同一任务打回 ≥2 轮 | 外循环反思：先怀疑契约/计划错，再怀疑实现错；换打法自主，换契约先问 | 打法自主/换契约先问 |
| 契约漂移 | 实现与 Produces 不符 | 二选一：改实现（打回）或改契约（先问人，批准后通知全部消费方） | 先问 |
| 新事实 | 执行中发现领域/环境约束 | Facts 入账本；核对未派发任务的验收标准，受影响即修订 | 自主 |
| 整体停滞 | 内循环计数超阈值，整批无合并进展 | 外循环：重排波次/收缩范围/升级人 | 重排自主/收缩范围先问 |

## 3. 计划与账本的结构规范

### plan.md 滚动波两区

- **锁定区**：本波次任务，任务书粒度，禁占位符（现有红线在此区全额适用）。
- **待细化区**：远期只到里程碑粒度，允许占位，但每条必须带**细化触发条件**（何时 + 依据什么事实细化）。进入下一波次前必须完成细化并过「并行批派发前自查清单」。
- 波次推进（本波全部合并）即**补给点**：用新学到的事实细化待细化区——滚动波的核心动作。

### ledger.md 双层

**任务账本区**（慢变量，重规划时更新）：

- **Facts**：已验证事实，每条附证据指针（文件路径 / 退出码 / 报告路径）。
- **Guesses**：假设，必须带**过期条件**（"当 X 发生即证伪"）；被证实→升级 Facts，被证伪→删除并记一笔。禁止静默留着，禁止当 Facts 派发。
- **计划版本**：`Plan vN`；每次变更追加变更日志行：`vN→vN+1 | 触发器 | diff 摘要 | 审批级`。

**进度账本区**（快变量，每事件追加）：

- 每个汇报事件一行：`事件 | 五问裁决（重点记第 2/3 问） | 下一步动作`。
- 会话记忆会被压缩，进度只认账本 + git log（`session-protocols.md` 的账本模板按本节双层结构落地）。

## 4. 计划变更分级审批

**自主记账**（改完账本即可，事后可审计）：

- 波次内任务重排 / 顺序调整
- 待细化区细化；验收标准措辞澄清（不改变判定命令与证据）
- 新增发现性小任务（补测试 / 顺手治理），不触契约与范围

**先问人类**（批准后才落账本与任务书）：

- 契约变更：接口签名 / Produces / Consumes 变化
- 范围变更：砍/换验收目标；新增/取消任务波次；放弃子任务
- 迁移号段等流水号资源重分配
- 主干合并与发布（沿用"四种停问情形"）

## 5. 红线

- 禁止无触发器改计划——"我觉得该改"不是触发器；每次变更必须能指认第 2 节某一行并记版本变更日志。
- 禁止 Guesses 无过期条件；禁止把 Guesses 当 Facts 写进任务书（输入只能是 Facts 或显式标注的假设）。
- 禁止改计划不改版本号与变更日志；禁止先改代码后补账本。
- 「先问」类变更未获批准，不得派发受影响的任务书。
- 计划变更先落账本再动口头安排（既有红线，与本机制叠加生效）。

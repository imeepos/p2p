# 回复裁决与防死循环：主会话是懒的回复者

主会话与子会话的健康单循环是「派发 → 子会话问 → 你裁 → 子会话收尾回报」。危险形态是中间的乒乓：问→答→再问→再答——每轮都烧双方上下文、都带排队延迟，而你的上下文是全局最稀缺资源，最先烧穿的一定是你。

目录：
1. 为什么必须懒（机制根据）
2. 回复裁决：三分类，默认略过

5. 错误纠正改道后续计划（不打断在飞会话）
6. 派发侧预防：把提问纪律写进任务书

## 1. 为什么必须懒（机制根据）

- 你发出的每一条消息都占用子会话一个回合边界（入队吸收），并把它拉回「与人对话」模式——回复本身就是打断税。
- 子会话把你的任何回复都当继续对话的邀请：你答得越快越随意，它问得越勤。随手回执会训练出确认式子会话。
- 发给子会话的消息只有一种存在理由：**裁决**。主会话的消息预算属于计划与裁定，不属于对话。

## 2. 回复裁决：三分类，默认略过

收到子会话消息，先问一句：**它是否阻塞在只有你能做的决定上？**

| 分类 | 特征 | 处置 |
| --- | --- | --- |
| 决策请求（阻塞） | 不回复它就无法继续：不可逆动作授权、契约/范围变更、资源冲突（撞号/撞文件）、跨任务裁决、预算突破 | **回复**：一次给全决策（§3），账本记 Ruling |
| 可自决请求 | 它有默认假设、选错了也可逆：实现细节、顺序取舍、临时方案 | **略过**：沉默 = 授权按其默认假设继续——这本身就是决策，账本记一行 |
| 非请求 | 进展汇报、终态（DONE/DONE_WITH_CONCERNS/BLOCKED）、复盘、确认收到、礼节、重发 | **略过**：收入账本即闭环；终态按验收协议处理，不回执 |

细则：

- **沉默是合法决策**，略过 ≠ 没处理：略过项账本记一行（`<sessionId> <消息摘要> → skipped（依据）`），防会话压缩后你自己忘记裁过。
- 拿不准是否阻塞时问：「它等我回复的这段时间会损失什么？」——损失可逆、能用下一张任务书补的，就略过。
- 略过不等于不看：内容涉险（如 CONCERNS 里的隐患）照常进验收清单，只是不发消息。

## 3. 回复质量：一旦回复，必须终止对话

- **一封一个决策点**：答案可判定（A/B 选谁、边界数值、是/否），不写「你们看着办」。
- **一次说全**：发送前预判它接下来会追问的 2–3 个问题，连答案一并给出。好回复让对话终止，坏回复让对话继续。
- **禁寒暄**：不确认收到、不复述对方内容、不鼓励、不解释自己的状态。
- **禁开放式邀请**：「有问题随时问」「欢迎继续沟通」一律禁用；收尾句式固定为「按此执行；新问题按默认假设自决并记入汇报，不必再问」。
- **定向单发**：一次只投一个会话。同一消息需要多个会话知道 = 它是全局约束，应进下一批任务书逐字下发，不是群发；禁止 `session_link_list` 枚举后群发打听（既有红线），也禁止同内容逐个复制投递的变体。
- 通道：需要答案的用 `talk`（有界超时，超时凭 claimToken `collect` 收），单向裁决用 `send`；一律不重发试错。验收核证据的追问合并成一封，不逐条发。

## 4. 单次问答（死循环刹车）

父-子交互尽量单向：运行期唯一合法的澄清问答形态是**子问父答，单次结束**——环路的根源就是第二轮。

- **子侧一次问全**：阻塞性疑问开工前批量一封（NEEDS_CONTEXT），此后不再有问答轮。
- **父侧一次答全**：按 §3 构造——预答它可能追问的点，以「新问题按默认假设自决并记入汇报」收尾。这一封就是问答的终结，不是对话的开始。
- **第 2 轮起停止回答**：子会话再次发来澄清请求，不回复——重写任务书重派（附已答决策），或令其带默认假设收尾、你验收时一并裁定。再次提问 = 任务书缺陷信号：指认是哪个字段没写清，并入下次派发前自查。
- **父对子的主动消息默认为零**：补充事实、解释、催促、确认一律不发，改写进下一张任务书逐字下发。仅三种例外：任务书派发（greeting）、修复轮验收反馈（附具体差距）、推翻型止损/收尾；`[补充]` 仅当该事实缺失会在下一检查点边界前造成浪费时排队直发（通道见 `steering-and-interruption.md`）。
- 问答回合记入账本。自查信号：**你发给某子会话的消息数 > 它问你的次数** = 你在制造对话，立即停手。

## 5. 错误纠正改道后续计划（不打断在飞会话）

发现某个在飞子会话的工作有错（做法/细节不对，方向未被推翻）：

- **默认不动**：不打断、不发纠偏消息。错处记入账本「后续纠正清单」，落到下一张任务书、修复轮或验收裁定里纠正——它跑完这一版，其可逆产物本来就要过你的验收。
- **打断的唯一合法条件是推翻型止损**：继续做 = 白做（计划已变/前提已失效），且剩余浪费 > 打断税（算术见 `steering-and-interruption.md` §3）。错误纠正 ≠ 止损：纠正的是它，止损救的是工作量。
- 确需送达的纠偏（如它即将基于错误契约做不可逆动作）：`[纠偏]` 排队到回合边界即可，不要求加速回执、不 interrupt——边界自然吸收，它本就按检查点节奏落盘。
- 本节是 `steering-and-interruption.md` 通道决策树的上游闸门：先问「能否改道后续计划」，答案是不能，才进那条决策树。

## 6. 派发侧预防：把提问纪律写进任务书

死循环的另一半根源在子会话侧，派发时就掐灭（模板已并入 `task-brief.md`）：

- 阻塞性疑问**开工前一次问全**（批量一封），NEEDS_CONTEXT 每任务至多一次——澄清问答全程只有一轮；
- 有默认假设的先自决、记入汇报，不为「确认理解」单独发消息；
- 主会话沉默 = 按你的默认假设继续，不是没看到；主会话只回答一次，不会有第二轮问答；
- 只回报决策请求与状态枚举，不发过程性播报。

## 7. 红线

- 禁止对进展汇报/终态/重发做确认式回复；略过项必须账本留痕。
- 禁止回复以开放式邀请收尾；回复必须含可判定答案并预答后续问题。
- 禁止同一消息群发多个子会话（含逐个复制投递的变体）。
- 禁止第二轮澄清问答——子问父答单次结束，第 2 轮起回炉任务书或令其自决收尾。
- 禁止为错误纠正打断在飞子会话；打断只留给推翻型止损。

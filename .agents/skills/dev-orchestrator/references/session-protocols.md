## 1. 会话生命周期总览（含工具面）

```
主会话（你，常驻）
  ├─ 建计划/账本 ──→ session_link_create 新建子会话 A（greeting=任务1任务书，worktree甲）──→ 轻量自验 ─┐
  ├─ 并行派发 ───→ session_link_create 新建子会话 B（greeting=任务2任务书，worktree乙）──→ 轻量自验 ─┤
  │                                                                      ↓ send_parent 回报
  ├─ 核证据（talk 追问 → 超时 collect 收取）→ 评审 → 合并进主干 → 主分支汇总检查 → 归档 A/B → 清 worktree/分支
  └─ 复盘：决策过账 / 踩坑喂给 self-evolving / 更新 TODO.md
```

- 一个任务一个会话一个 worktree；会话从不直接互相对话，一切经你流转。
- 工具面（session-link 插件，全部限同工作区）：
  - `session_link_list` —— 查本工作区会话（id / blank / running），找目标只此一处
  - `session_link_create` —— 新建子会话并投任务书；`greeting` 必带（空会话 blank 隐藏），`title` 用任务名
  - `session_link_send` —— 单向投递（派反馈、补材料，不等回复）
  - `session_link_talk` —— 提问并等回复（默认超时 120 秒）；超时结果带 `claimToken`
  - `session_link_collect` —— 凭 `claimToken` 收取迟到回复，暂无回复快速返回，不重发
  - `session_link_send_parent` —— 子会话回报派发者（自动解析上级，无需 id）；禁群发
- 你负责派发、验收、合并、归档；子会话负责实现与轻量自验。
- **等待纪律（事件驱动，禁止轮询）**：派发后你的回合即告结束——子会话的汇报（终态 STATUS 或中途补充）送达时自动唤醒你，不需要也不允许 `sleep N; date; ls ...` 式循环盯梢。等待窗口是流水线时间：写下一张任务书、细化待细化区、跑主干汇总检查；找不到活先过找活扫描（`work-finding.md` §2，被唤醒续轮先跑心跳清单），扫描过完仍无可做才干净结束回合。唯一合法的一次性进度动作是验活（`parallel-playbook.md` §4），一次即止。
- **通道语义（中途修正）**：发往 running 会话的消息入队到**回合边界**才被吸收（无工具间隙抢占）；后台子代理可用 `interrupt_agent` 取消当前回合（已入队消息仍停着，需再 send）。中途修正的选路、模板与止损算术见 `steering-and-interruption.md`。

## 2. 新建 vs 复用

默认**新建专属会话**：`session_link_create`（workspacePath=当前工作区，title=任务名，greeting=任务书全文）。greeting 必带——blank 会话在侧边栏隐藏，也收不到任务。

唯一允许复用的情形：同一任务的修复轮（第 1–3 轮），向原会话（账本里记的 sessionId）`session_link_send`/`talk` 投具体反馈——它已有任务上下文，重开反而丢失。以下一律新建：

- 新任务（哪怕和旧任务只差一点）——上下文污染比初始化成本贵
- 修复轮 ≥ 第 4 轮——原会话大概率已带死胡同思路，换新会话并补强上下文
- 历史会话的状态存疑——不猜，开新会话从账本恢复

## 3. 账本（ledger）：模板与恢复规则

每轮迭代一个账本目录（git 忽略的草稿区即可，如 `.scratch/<YYYY-MM-DD>-<slug>/`，目录名由项目自定），放账本、任务书、子会话汇报。**会话记忆会被压缩，进度只认账本 + git log；凭记忆重派已完成的任务是最贵的事故。**

```markdown
# Orchestrator 账本 — 计划: <TODO.md 章节 / 计划文件路径>
## 任务
- T1 <名称>: complete (<分支> <commit>) — <一句话结论>
- T2 <名称>: dispatched (sessionId=<id>) → fixing R2（反馈：<要点>）
- T3 <名称>: pending（依赖 T2 的 <Produces 项>）
## Rulings
- Ruling: <裁定> — <依据> — <错了的代价>
## Handoffs
- <时间> <会话> → <会话>：<交接了什么>
```

> 账本双层结构升级（Facts/Guesses 分离、计划版本+变更日志、进度账本五问裁决行）的完整规范见 `adaptive-planning.md` 第 3 节；本模板是其最小骨架，长周期多波次的轮次按该节展开。

恢复规则（新会话或压缩后接管时）：

1. 账本首行确认是本计划的账本，别人的账本不读不写。
2. 已标 complete 的任务不重派，先去 git log 验证 commit 真实存在。
3. 最后一条是修复轮的任务从下一轮续（向该 sessionId 继续投递），不开新循环。
4. 账本与 git log 冲突时，以 git log 为准并在账本记一笔修正。

## 4. Handoff note 模板

跨会话交接（任务接力、修复轮换会话、你被要求换人接管）时随任务书附上：

```markdown
# Handoff: <从哪> → <到哪>（<日期>）
## 现状摘要
<3 句以内：做到哪、距验收差什么>
## 必要上下文
<接管者无法自己查到、但不知道必翻车的事实：约定、坑、环境>
## 下一步
<按序号列出，第一步必须可直接执行>
## 已定决策及理由
<决策 → 为什么 → 放弃了什么；被推翻的旧决策注明>
```

写完自查：接管者只凭这张纸 + 仓库，能否不问任何人开始干活。

## 5. 主分支汇总检查清单

合并后你在主干亲自核（或派只读评审会话核），全绿才算本轮完成：

- [ ] 所有子任务分支已合并（`git log` 实证），worktree 收尾各步独立执行过
- [ ] 完整门禁四件套通过：lint + test + build + commit（记录退出码，不信"应该绿"）
- [ ] 行为证据抽查：至少一个用户旅程级集成测试真实跑过；接口返回解析业务信封而非只看 HTTP 200
- [ ] 跨任务一致性：相邻任务的 Produces/Consumes 实际对上；共享资源（路由/权限码/迁移号）无撞号
- [ ] 账本全部闭环；未落地的发现转 TODO.md 或记 Known Issues
- [ ] 不可逆决策已过账 `docs/notes/adopted/`；新踩坑已喂给 self-evolving

## 6. 归档清单

子会话归档的前置条件（缺一不归档）：

- [ ] 该任务验收标准逐条有证据，评审结论为"通过"或残留项已裁定放行
- [ ] 分支已合并进主干，主干汇总检查通过
- [ ] worktree 已 remove、分支已删（本地 + 远端）
- [ ] 子会话的汇报已收入账本，handoff 事项已转给下游
- [ ] 以上全绿 → 归档子会话（宿主操作，**不可逆且全面禁用**：归档后 send/talk/collect 一律拒绝，再也不收不到它的回复）→ 账本记一行 `archived <sessionId>`

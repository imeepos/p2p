# 并行效率手册（Parallel Playbook）

> 目标：在不破坏隔离与验收纪律的前提下，把并行度拉到任务结构允许的上限。
> 原则：隔离买速度，契约买正确，单一汇合点买秩序，行为证据买信任。
> SKILL.md 只留规则；本文件是做法与自查清单——制定计划时、并行批派发前通读。

## 目录

1. 串行链压缩（契约钉主干）
2. 资源预分配（防撞号）
3. 流水线重叠与随过随合并
4. 派发后验活（子会话死亡处置）
5. 并行批派发前自查清单

## 1. 串行链压缩（契约钉主干）

依赖图上每条串行边 A→B，先问一句：**B 消费的是 A 的签名，还是 A 的实现？**

- 只消费签名（函数签名/类型/路由挂载点/信封字段）→ 可拆。
- 消费真实实现（行为/数据流/存储）→ 保留串行；硬拆 = 集成灾难。

拆法：

1. 计划期把被消费的签名固化成契约：直接落一个可编译的最小桩（接口 + 未实现 panic/TODO），或一份类型契约文件。
2. 契约作为**独立小提交**先合入主干（`type(scope): contract ...`），保证可单独 revert。
3. A 实现该契约；B 对着契约开发，用自己的桩做测试替身——两者并行，互不等待。
4. 合并顺序即集成点：先合 A（真实实现落地）；B 合并前 rebase 主干、删自己的桩、对真实实现重跑门禁。

红线：

- 契约提交只含签名/类型/桩，禁夹带实现——否则 revert 面扩大，并行优势清零。
- B 的测试替身必须与契约同源（import 契约类型/常量，不抄字面量）；A 落地后 B 必须用真实实现重跑集成路径——桩替身绿 ≠ 集成绿。
- 契约变更走计划变更流程：先改账本，再通知全部消费方，最后改代码。

收益量级：3 任务串行链 `A→B→C` 压成 `A∥B→C` 甚至 `A∥B∥C`，关键路径缩短一整个任务的时长。散文计划与依赖图矛盾时，信依赖图（契约互证）。

## 2. 资源预分配（防撞号）

worktree 只隔离文件，**不隔离流水号资源**。并行派发前，把所有全局唯一资源在计划期一次性分段并写进各任务书：

| 资源 | 预分配方式 |
| --- | --- |
| 数据库迁移号 | 每任务一段（如 T2=0010-0019、T3=0020-0029） |
| 业务错误码 | 每域一段（T2=1000-1999、T3=2000-2999…） |
| 权限码 | 中央登记文件 + 命名段约定，append-only 独立小提交 |
| 路由前缀/挂载点 | 中央登记点注释预占位 |

派发前重核号段：本树 `ls migrations/*.up.sql | tail` + 逐未合并分支 `git ls-tree <分支> -- migrations/`。撞号让位：**已进主干者优先，后来者让号改名**——未进库的改名零成本，合并后改是事故。

共享文件纪律：各任务需要同构配置时（sqlc.yaml 类），**按域拆文件、每域一份**，禁止共用单根文件——单根文件是确定的合并冲突点，每轮合并必撞。共享根文件清单入账本。

## 3. 流水线重叠与随过随合并

验证是流水线，不是关卡。三类工作重叠跑，不让任何一环空等：

- 评审会话在看任务 N 的 diff 时：任务 N-1 若已过验收 → 立即合并；任务 N+1 的任务书同时开写。
- **随过随合并**：任务过验收就合并，不攒批——攒批 = 冲突面最大化 + 下游消费方被无谓拖住。
- 合并前只做协议动作（rebase 主干 + 门禁四件套），合并后主干汇总检查；每任务同款 runbook，机械执行不临场发挥。

## 4. 派发后验活（子会话死亡处置）

宿主重启/守护进程更新会**静默杀死在飞子会话**，无任何报错信号（本项目实证：派发后 worktree 零提交 = 全部成果蒸发）。处置：

1. 派发时任务书要求**早落盘小步写**：进度文件先落 worktree（防中断留痕），实现分小笔提交——盘上产物是存活权威。
2. 派发后**一次**验活：单次检查 worktree 是否出现进度文件/提交/stash 迹象。验活是一次性动作，不是轮询许可——此后等待全部靠汇报送达的事件通知，禁止 `sleep` 循环盯梢。
3. 零迹象且超合理时长 → 判定可疑死亡：账本记原 sessionId 死亡 → 新会话重派（不续用原会话）；worktree 与分支复用，盘上已有产物接续。
4. 验活与重派是编排动作，不需请示；账本必须闭环记录两次派发。

## 5. 并行批派发前自查清单

- [ ] 依赖图每条串行边都问过"签名还是实现"，可拆的已拆
- [ ] 全部流水号资源已分段，且逐字写进各任务书
- [ ] 无跨任务共享的根级文件（同构配置已按域拆）
- [ ] 各任务书 Produces/Consumes 闭合：每个 Consumes 都对应别人的 Produces 或主干契约
- [ ] 每条验收标准可判定（命令 + 证据）
- [ ] worktree / 分支 / 号段对照表已记账本
- [ ] 验活时点已定（派发后何时查第一次落盘迹象）

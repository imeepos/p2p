# 任务类型规范：前端页面（frontend）

目录：1. 何时打此标签 → 2. 任务书差异 → 3. 验收门 → 4. 高频坑 → 5. 深入阅读

## 1. 何时打此标签

页面/组件/样式/交互/设计稿还原/UI 走查/无障碍类任务。产出物是"用户看得见的界面"，验证靠渲染证据而非单元断言。

## 2. 任务书差异（在通用模板上追加）

**验收标准按"视觉验证回路"写**，禁止"页面正确显示"这类不可判定表述：

- 基础回路（官方模式）：`实现设计 → 起服务截图 → 与设计稿逐项对比列出差异 → 修复后再截图`，截图路径写进产出物
- 无设计稿时改为规范自检：对照项目 design token 清单逐项声明（颜色/间距/圆角/字号/布局/层级六维）
- UI 必须补齐三态：loading / 空态 / 错误态——缺失即验收不通过

**必带约束（逐字进任务书）**：

- token 纪律："禁止内联 hex/px，一律走项目 token 变量（清单见 `<路径>`）"
- 资产纪律："引用的图片/图标资产必须已存在于本地 `<路径>`，禁止凭空写 src"（防 AI 脑补 404）
- 复杂页面拆分规则：>3 屏或 >100 节点 → 拆成组件级任务派发，每组件独立会话；整页一次性生成禁止

**必读输入**：设计规范文件（DESIGN.md / token 清单 / 设计稿路径）+ 项目 UI 栈说明。

## 3. 验收门（主会话机械核验）

- [ ] 改动前/后截图证据存在，路径与任务书产出物一致
- [ ] console 零新增报错（贴出 console 输出或截图）
- [ ] 与设计稿的差异清单：每条写"位置 + 设计稿是什么 + 实现是什么 + 怎么修"，或声明已逐项核对一致
- [ ] 无固定像素魔法数（宽高走 flex/百分比/token）；状态未挤在单一 state；三态齐全
- [ ] 涉及表单/交互的组件：可访问性基础项（label 关联、键盘可达）未被破坏

## 4. 高频坑与对策

| 坑 | 对策（写进任务书或验收） |
| --- | --- |
| 上下文压缩静默吞掉空态/异常态/悬浮元素 | 拆组件独立会话；整页生成后专门派一轮"三态补齐"任务 |
| AI 自己编字段名（docCount/fileNum/total 混指同一数据） | 任务书给出字段清单与真实命名，禁止自创 |
| 样式漂移（每会话重新发明间距颜色） | token 引用语法 + "生成任何 UI 前先读 `<规范文件>`" |
| 生成"能用但不可维护"（固定宽、巨型 state、零错误处理） | 合入前强制一轮重构任务：重命名/拆状态/补三态 |
| 工作流绑定单一生成工具的质量 | 产出物必须是项目工程内的普通代码，可脱离生成工具维护 |

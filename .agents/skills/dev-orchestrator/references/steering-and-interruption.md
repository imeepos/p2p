# 中途修正：排队、纠偏、打断与重派

子会话在飞时计划有变——发送前先过本协议。目录：

2. 发送前三问与通道决策树

4. 预防：用任务书把边界变密（最重要）

## 1. 通道语义（机制事实，别赌）

- `session_link_send` / `session_link_talk` 投给 running 中的会话：消息**入队，回合边界才被吸收**。修正延迟 = 当前回合剩余时长；宿主没有"工具调用间隙注入"的抢占通道。
- 后台子代理（subagent 工具创建、有 agent id）：`interrupt_agent` 取消其**当前回合**，上下文保留；已入队消息停在原地，需再 `send_message` 才会以新回合处理。
- `talk` 的有界超时是问答等待，不是抢占；超时凭 claimToken `collect` 收迟到回执。
- 结论：**"发出去马上被看到"不成立**。紧急修正只有三个杠杆——排队吸收（靠边界密度）、打断（有原语时）、重派（无原语时）。

## 2. 发送前三问与通道决策树

发送任何修正前过三问：

1. **性质**：补料（不改变方向的补充）／纠偏（方向对、做法或细节要改）／推翻（计划变了，继续做=白做）？
2. **边界距离**：按任务书检查点节奏，当前回合距下一个检查点还有多远？（近 = ≤1 个检查点单元）
3. **固化风险**：等到边界，错方向的工作会固化多少？（未提交草稿 < 已提交 < 已合并/推送）

| 性质 ＼ 通道 | 边界近 | 边界远且固化中 |
| --- | --- | --- |
| 补料 | **排队**：`[补充]` 直发 | **排队**（打断税不值） |
| 纠偏 | **排队**：`[纠偏]` 直发，边界自然吸收 | **加速**：`[纠偏]` + `talk` 要回执；有打断原语则先 `interrupt_agent` 再 `send_message` |
| 推翻 | **止损**：打断（有原语）；无原语则**重派 + 给旧会话发 `[收尾]`** | **立即止损**，一步都别让它多跑 |

session-link 会话没有打断原语：推翻型 = 新会话带修正版任务书重派 + 旧会话发 `[收尾]`（让它在下一个边界停止扩张，而不是跑到自然结束）+ 旧分支/worktree 按废弃处置不合并。

## 3. 止损算术（打断税）

打断与重派不是免费的：**打断税 = 子会话重建上下文 + 半成品盘点 + 修正上下文重发**。继续跑的浪费 = 剩余工作量 × 错方向占比。

判据：**继续跑的浪费 > 打断税 → 动手；否则排队**。纠偏只影响最后 20% 工作时，让它跑完边界再改更便宜。

## 4. 预防：用任务书把边界变密（最重要）

通道没有抢占语义，**回合边界的密度就是修正延迟的上限**。任务书三件套（已并入 task-brief 模板）：

1. **检查点节奏**：每完成一个可提交单元（一个文件/一组测试/一个函数簇）→ 落盘 + commit + 进度账本一行；预估工作量切成 ≤5 个检查点——单个检查点预估超约 10 次工具调用，基本是两件事。
2. **收到消息的行为契约**：`[补充]` 合并进当前工作、不重做已完成部分；`[纠偏]` 当前工具调用完成后停止推进新工作，先回执再按新指令继续；`[收尾]` 完成当前检查点落盘后即报 DONE_WITH_CONCERNS 停止。
3. **不可逆动作钉在检查点上**：删除、合并、推送、改共享文件，只允许在检查点边界发生且默认先请示——保证任何时刻打断，盘上状态都是干净的检查点。

## 5. 消息模板

**`[补充]`（排队）**

```text
[补充] 不改变方向，按原任务书继续。
补充事实：<路径/约束/接口签名…>
用法：<哪个环节用上；与任务书冲突时以__为准>
```

**`[纠偏]`（排队或打断后）**

```text
[纠偏] 当前工具调用完成后停止推进新工作，先回执确认。
变更：<哪条要求变了：旧 → 新>
原因：<一句话：触发源>
保留：<已完成的 X/Y 不动，可复用>
废弃：<Z 的产出不要，勿再扩展>
下一步：<修正后的动作，可直接执行>
```

**打断后重发**（`interrupt_agent` 之后必发——队列里的旧消息不会自己活过来）：

```text
已取消你当前的执行回合——不是任务失败。先从盘上同步状态（git log + 进度账本 + 半成品清单），再按以下指令继续：
<粘贴 [纠偏] 模板全文>
```

**`[收尾]`（重派时发给旧会话）**

```text
[收尾] 本任务已被重派替代。完成当前检查点的落盘与 commit 后即停止，报 DONE_WITH_CONCERNS（备注：任务重派），不再推进任何新工作；未完成事项无需交接，新会话已接管。
```

**重派修正任务书**：新会话 + 修正版任务书，复用 `session-protocols.md` handoff 四段式，额外附「修正 diff」——原任务书哪几条作废、盘上产物哪些复用哪些废弃。
纠偏/打断用 `talk` 发（要回执），超时凭 claimToken `collect` 收，不重发。

## 6. 留痕与修复轮计数

- 每次打断/重派记账本一行：`Interrupted/Redispatched <sessionId> — <性质> — <止损：省掉的估计工作> — <复用产物>`。
- 修复轮衔接：`[纠偏]` 计入修复循环计数（R+1，熔断规则不变）；`[补充]`、`[收尾]` 不计。
- 被打断不是子会话的污点：其复盘照常收集——它是重规划的情报源。

## 7. 红线

- 推翻型禁止排队了事——明知道在做白工还让它跑完，是最贵的浪费。
- 补料禁止打断——打断税白交。
- 打断只服务于止损与改向；禁止用打断催进度、表达焦虑（等待纪律的姊妹条款）。
- 打断前先看盘上产物（git log + 进度文件）；修正指令必须写明保留/废弃清单——否则子会话重建状态时会把半成品当垃圾或当宝贝。
- 队列里的旧消息不因打断消失：打断后重发指令时，检查是否需要一并撤销/覆盖旧消息的内容。

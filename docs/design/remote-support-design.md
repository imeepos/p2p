# 远程电脑支持服务（AI 维修坐席）—— 产品与协议设计 v0

> 状态: 草案 v0（待评审） | 日期: 2026-09-04
> 依赖: [p2p-base-design.md](p2p-base-design.md)（通信底座）、[wire-protocol.md](wire-protocol.md)（协议 ID 语法与登记点）、
> [acp-over-p2p-design.md](acp-over-p2p-design.md)（续连窗口/审批超时等机制蓝本）
> 定位: 底座之上的应用层商业方案。不改通信内核；新增 `/rsh/1` 应用协议、客户机薄执行器、
> harness 侧 fs/bash 远端后端适配。本文只做设计与裁决记录，不含实现。

## 1. 商业场景与产品定义

用户电脑出问题自己解决不了，付费找人处理。存量供给是人工远程支持
（向日葵/TeamViewer + 人工坐席，单均 ¥50-200，付费意愿已被市场验证）。
本产品把"那个人"换成 AI：**服务商侧的 DSH 会话在用户授权且付费的前提下，
远程操作客户机的文件系统与命令行**，完成诊断与修复。

本轮已拍板的商业参数：

| 参数 | 拍板 | 理由 |
|---|---|---|
| 平台 | Windows 10/11 优先 | 付费求助人群最集中；UAC 弹窗天然是一层确认机制 |
| AI 自主度 | v1 playbook 化 | 每类问题预定义诊断/修复/验证步骤集，AI 只做步骤内自适应，不自由发挥 |
| 收费 | 免费只读诊断 + 按单付费 | 免费体检是获客钩子兼 AI 预分类定价依据；会员制后置 |
| 兜底 | 复杂单转人工坐席 | 目标 AI 闭环 60%+；人工单定价更高 |

v1 问题目录（8 类，playbook 逐个人工打磨）：
电脑卡慢 / 弹窗流氓软件清理 / C 盘空间不足 / 网络掉线诊断 / 软件装卸修复 /
打印机驱动 / 蓝屏日志初筛 / 浏览器劫持。

## 2. 第一公理与拓扑裁决

**第一公理：客户机端点不含任何 AI 能力（无模型、无 prompt、无 playbook）。**
agent 若落在客户机，客户装上 DSH 就不再需要本服务——产品亲手交付了核心价值。
因此唯一可行拓扑是 C：**大脑在服务商侧，客户机是受控的哑执行端点**。

| 拓扑 | 形态 | 裁决 |
|---|---|---|
| A | agent 落客户机（DSH 现成 libp2p 桥方向） | 否决：违反第一公理 |
| B | agent 落客户机（自研底座 + /dsh-acp/1） | 否决：同上 |
| **C** | **服务商 DSH 远程操作客户机 fs + 命令行** | **采纳** |

C 的两个结构性收益：

1. **信任倒置**：策略执法点在客户机本地。"AI 能做什么"由客户机名单引擎独立裁决，
   服务商侧的风险标签只是建议——服务商被劫持或有 bug，客户机仍把得住门。
   "谁的主机谁做主"是与人工远程支持的本质差异，也是营销主打点。
2. **商业动作即权限动作**：免费诊断 = 只读 scope；支付 = 工单系统下发新 grant
   解锁写通道。"交钱"在架构上就是一次 scope 升级，天然杜绝未付款动手。

harness 侧落点依据（2026-09-04 已核实）：

- fs 工具后端可插拔：`packages/fs/tool-fs` 的 read/write/edit/grep 统一经 `ctx.fs` 解析路径；
- **远端执行先例**：`packages/fs/fs-e2b`（"Remote filesystem backend sharing the sandbox
  owned by `ctx.e2b`"）——把 E2B 换成客户电脑、E2B SDK 换成自研 p2p 通道，即为 `fs-p2p`；
- 逐调用策略栅栏形状：`packages/fs/fs-sandbox`（per-call policy fence）。

结论：C 拓扑在 harness 里不是新架构，是已验证形状的换芯。

## 3. 总架构

```
服务商侧（大脑+知识资产，永不下发）            客户机（薄，Rust，无任何 AI）
┌──────────────────────────────┐            ┌──────────────────────────────┐
│ DSH 会话（每工单一个）          │            │ 「维修助手」薄执行器            │
│ ├─ playbook skills（8 类）     │  QUIC 直连  │ ├─ p2p node（自研底座）        │
│ ├─ fs-p2p 后端（对标 fs-e2b）   │◄═════════►│ ├─ fs 子协议：结构化文件操作    │
│ ├─ bash-p2p 后端              │ /rsh/1     │ ├─ shell 子协议：命令帧执行    │
│ ├─ 坐席控制台（1 坐席 N 单）    │  打洞/中继  │ ├─ 本地名单引擎（权威执法）     │
│ ├─ 工单/支付/审计归档          │            │ ├─ 托盘：授权/审批/急停        │
│ └─ LLM key（永不离开本侧）     │            │ └─ 审计日志 + 备份钩子         │
└──────────────────────────────┘            └──────────────────────────────┘
```

| 组件 | 形态 | 职责 |
|---|---|---|
| 维修助手 | Windows 安装包（Rust bin） | 连接、执行、本地执法、审批 UI、审计、备份钩子；不含任何 AI |
| /rsh/1 | 底座应用协议 | fs / shell / 审批 / 控制四族帧 |
| fs-p2p / bash-p2p | harness 后端包 | 对标 fs-e2b 形状，把 ctx.fs 与 bash 执行路由到 /rsh/1 |
| 坐席控制台 | Web | 工单监管、操作流实时视图、escalation 人工接管 |
| 工单/支付 | Web | 录入→体检→报价→支付→发 grant→关单归档 |
| playbook skills | DSH skills | 8 类问题 ×（诊断/修复/验证）步骤集 + 红线清单 |

## 4. 工单与权限生命周期

```
工单录入 → 免费只读体检（diag scope：fs 只读 + 白名单诊断命令）
  → AI 预诊断分类 → 报价 → 用户支付
  → 工单系统下发 fix grant（一次性 token，绑工单+PeerId，默认 2 小时时效）
  → 客户机托盘弹窗授权（本次允许的操作类别与时效）
  → 诊断报告 + 步骤级修复方案 → 用户批准
  → 执行：低风险自动跑；敏感写逐条托盘审批；高危写前自动还原点/备份
  → 验证 playbook 确认 → 成功关单 / 失败回滚或转人工
  → grant 立即失效 + 审计双向归档
```

要点：**支付在架构上 = scope 升级**（diag 只读 → fix 可写但需逐条审批）。
token 属性：一次性、绑定工单与对端 PeerId、带时效、关单即焚。

## 5. 线协议 /rsh/1

协议 ID 命名遵循 wire-protocol.md §3.1 语法，实现期登记进 p2p-relay `proto_ids`
（底座唯一定义点）。复用底座既有设施：varint 长度前缀帧、chunked transfer、
有界双向对拷；握手帧是协议唯一插入点，之后对字节透明（同 acp 桥哲学）。

| 帧族 | 帧 | 关键字段/语义 |
|---|---|---|
| 握手 | hello / ready / denied | ticket token + scope(diag/fix) + caps；denied 可观察但不泄露策略细节 |
| shell | cmd / result | **argv 数组**（非拼接字符串，防注入）+ cwd（钉授权根）+ timeout_ms + risk + **reason**（AI 给用户看的一句话人话）；result 含 exit/stdout/stderr/截断标志 |
| fs | read_file / write_file / list / glob / grep / stat | 结构化通道不走 shell；write_file 必须携带 diff 预览供审批 |
| 审批 | approve_req / approve_res | 60s 超时 = 拒绝（无人值守即拒绝，沿 acp 红线） |
| 控制 | kill（急停）/ ping / audit_sync | 急停双向：托盘与坐席台均可发起 |

拍板项：

1. **双通道分离**：fs 走结构化帧（可校验路径监狱、可 diff 审批），shell 走命令帧；
   能用 fs 通道完成的一律不走 shell。
2. **路径监狱**：所有路径参数强制解析在授权根目录内，越界即拒（平移 acp 的 cwd 改写思路）。
3. **输出门禁**：单帧 ≤1 MiB（底座约束）+ 单命令输出上限 + 截断标志，杜绝内存炸弹。
4. **断线语义**（平移 acp-over-p2p §5）：执行中断线，客户机把当前命令跑完、结果进缓存；
   续连窗口（默认 90s，可配）内重连补放；窗口过期走会话恢复；
   **审批请求遇断线一律拒绝**。

## 6. 安全模型：双端执法

| 层 | 机制 | 执法点 |
|---|---|---|
| L1 授权 | 会话授权弹窗：范围 + 时效，用户主动发起 | 客户机 |
| L2 分级 | 每条命令/文件操作预分类 read/write/danger | 双端（发送侧打标，接收侧独立重判） |
| L3 确认 | 敏感写逐条托盘审批（注册表/删除/网络配置/凭据相关） | 客户机（权威） |
| L4 兜底 | 高危写前自动还原点/文件备份；一键回滚 | 客户机 + playbook 步骤强制 |
| L5 观测 | 托盘实时命令横幅 + 双向全量审计留存 + 急停 | 双端 |
| L6 合同 | 电子授权书、赔付上限、责任保险 | 平台层 |

红线（客户机无条件拒绝，不提供任何开关）：format/低级磁盘操作、触碰密码凭据、
加密用户文件、批量删除、使杀毒软件失效。

发送侧（DSH）的 fs-sandbox 形状策略栅栏是 UX 与效率层（明显越界快速失败）；
**权威执法永远在客户机**。审计双向各存一份完整操作流，责任认定零争议。

## 7. 客户机端点：「维修助手」

- 形态：Rust bin + 托盘 UI；安装包需代码签名（SmartScreen 硬成本，预算必列）
- 会话外不自启、不留驻后台连接；安装只装执行器，不装任何 AI 组件
- 内存门禁进验收：付费求助主力是低配老机器，执行器常驻内存目标 < 50 MB
- UAC：系统级修改由 Windows UAC 弹窗自然拦截确认（免费的一层执法）

## 8. 服务商侧平台件

- DSH 会话池：每工单一个会话；fs-p2p / bash-p2p 两个后端包对标 fs-e2b 形状
- 坐席控制台：1 坐席监管 N 单，工具时间线可视，escalation 时人工接管对话
- LLM key：大脑在服务侧，key 从未离开（C 拓扑结构性优势，无需网关 token 方案）
- playbook skills：步骤集内 AI 自适应（解析输出、走异常分支）；红线清单进 skill 强制
- 审计归档：会话 transcript + 命令流双向留存，对接电子授权书与赔付流程

## 10. 风险与对策

| 风险 | 对策 |
|---|---|---|
| AI 误操作损坏用户数据 | 双端执法 + 逐条审批 + 自动备份/还原点 + 责任保险；赔得起再开门 |
| 合规（PIPL 个人信息） | 默认不读取个人文件；诊断数据脱敏；留存边界待裁决（Q5） |
| 通道被滥用变后门 | token 一次性 + 绑 PeerId + 时效 + 关单即焚；客户机红线无条件拒 |
| AI 解决率不足 | 人工坐席兜底层；P0a 先用真单验证再投入开发 |
| 未签名安装包被 SmartScreen 拦 | 代码签名证书硬成本 |
| 低配客户机资源 | 执行器 <50 MB 内存门禁；大输出截断 |

## 11. 明确不做（负空间即设计）

- 客户机不放任何 AI 组件（第一公理，无例外）
- v1 不做自由 agent（无 playbook 护栏的裸 DSH 会话）
- 不做无人值守修复（审批超时即拒绝；owner 不在场 = 停）
- macOS / 移动端不进 v1
- 不做 durable 权限、不凭据上 wire、不自定义加密（全用底座既有安全层）

# p2p GUI 体验走查审计（2026-09-07）

审计人：p2p GUI 体验审计员（AI）。范围：apps/gui 全部 14 个页面视图。仅审计，未改任何代码。

## 走查方式与环境

- 页面均基于真实运行实例走查：mock IPC dev 模式（`VITE_MOCK_IPC=1`，vite dev）+ 仓库工具 `node scripts/gui-agent.mjs`（eval / click / errors），另用等价 CDP 巡游器（gui-agent 同款机制，存于 /tmp，不入仓库）一次会话截取 13 条路由截图与 DOM 快照（产物在 `/tmp/gui-audit2/`，含 tour-report.json 与逐页 png，供复核）。
- 环境备注 1：本机存在 `apps/gui/.env.development.local`（`VITE_MOCK_IPC=0`），会覆盖仓库默认的 mock 态——浏览器直开这种实例时全部页面 console 报 invoke undefined、好友簿恒空。走查用 shell 变量显式 `VITE_MOCK_IPC=1` 的独立实例完成。建议负责人知悉该本地覆盖的存在。
- 环境备注 2：5173 端口被一组先行启动的 `tauri dev` 链占用（属并行会话，未触碰）；审计实例跑在 5175（为避开两 vite 实例共享 `.vite` 优化器死锁，用了隔离 cacheDir 的等价配置，仓库零改动）。
- 环境备注 3：mock 态下好友关系需「对方同意」才成立，单浏览器无法闭环，故「发消息/群聊」的部分反馈链路以代码推断补齐，均标注【代码推断】；其余结论均为页面实测。
- 每条 finding 标注问题域：1 操作路径 / 2 按钮反馈链路 / 3 表单 / 4 表格 / 5 选择器。优先级：P0=反馈链路断裂、删除无确认、选择器不可用/不一致、高频操作路径过长、表格显示内部编号；P1=明显摩擦或一致性缺陷；P2=打磨项。

## 与 9/5 基线的增量关系

基线：docs/notes/2026-09-05-ui-ux-audit-and-dispatch.md（其 P0/P1/P2 已经 UI-A/B/C/D 四包修复合入，账本 53 done）。本轮为**增量审计**，不重复报告基线已修复项；走查中对基线项做了抽查复核，结果：

- 确认已修复（本轮实测/代码复核通过）：IME 组合态回车守卫（composer 挂 use-ime-composition）；ACP/Agent 停用与删除二次确认；设置保存失败聚焦反馈（focus-first-error）；mDNS 单一保存模型与「重启生效」说明；事件订阅失败态有原因+重试（真实 IPC 实例实测）；诊断「一键清理」确认弹窗（实测 alertdialog，非回归）；宣告/观测白话用途说明；⌘K 按钮常驻且面板覆盖全部页面；rendezvous 单一添加地址入口；ErrorBoundary 提供重试出路（诊断页失败态顶部出现「重试」）。
- 疑似回归：无。走查中曾出现「Reload/Details 英文兜底」疑点，经查为 dev 服务器进程死亡后的 Chrome 连接错误页，非应用行为，已排除。
- 本轮重心按任务书五维度，聚焦基线未覆盖的：表单分组与选择器化（F03/F11/F13/F24/F25）、表格关联名称可读性与删除关联检查（F02/F12/F18/F21）、全局选择器一致性（F03/F23）、操作步数（F01/F09/F15/F17）。
- 表格「删除关联检查」结论：Agent 删除明示「同时移除本地会话记录索引」、好友移除明示「不删本地消息历史」、引导地址删除明示「需重启生效」——关联后果均有表达，通过。
- 表格「检索/分页/统计」结论：peers（PeerId/地址）、chat 会话、events 内容三处即时检索齐备；分页在当前数据规模（mock 个位数行）不构成需求，性能虚拟化属基线 DEBT2，本轮不重复报告。

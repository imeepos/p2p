# p2p-base 通信协议接入文档

状态：v1，与 2026-09-06 main 分支代码对齐。事实基线为 `crates/` 代码与
[../design/wire-protocol.md](../design/wire-protocol.md)（v1 字节级规范）；
两者冲突时以代码为准，文档只登记漂移不倒改代码。

## 1. 文档定位

本目录是 p2p-base 底座的对外协议文档，面向**不阅读本仓库源码**的第三方开发者。
目标：仅凭本文实现一个兼容的 P2P 节点（能与本栈互认、互通、互发现），
或把自定义业务协议接入本栈。

p2p-base 是一个安全优先的 P2P 通信底座：节点身份即密钥（PeerId 由公钥哈希推导），
QUIC 与 TCP 双传输路径均在握手期完成加密与身份互认，其上是流复用、统一帧格式、
协议 ID 路由，再往上提供 mDNS 局域网发现、rendezvous 跨网注册查询、打洞与中继降级链。
第三方只需实现线协议语义即可互通，不依赖任何本仓库二进制。

## 2. 读者与前置知识

- 读者：为自有应用接入 p2p 网络的应用开发者；实现兼容客户端/服务端的协议工程师。
- 前置：TCP/UDP 基础；对 TLS、Ed25519 签名、protobuf 有概念级了解即可，
  全部关键算法语义在正文给出，不要求预读任何源码。
- 验证工具：任意能收发 UDP/TCP 并计算 SHA-256/base58 的语言环境。

## 4. 术语表

| 术语 | 定义 |
|---|---|
| 节点身份（Keypair） | Ed25519 密钥对，32 字节种子唯一确定；种子即身份，须 0600 落盘 |
| PeerId | 节点公开标识：base58(SHA-256(ed25519 公钥原始 32 字节))，定长 32 字节摘要 |
| 种子文件 | 裸 32 字节 Ed25519 种子文件；加载时收紧权限，长度不符即报错不静默重建 |
| 传输地址 | `IP/u端口`（QUIC）或 `IP/t端口`（TCP），如 `1.2.3.4/u3400` |
| SecureConn | 已完成安全握手并互认对端 PeerId 的连接；其上可开多条逻辑流 |
| 复用层（mux） | 一条连接承载多条逻辑流：QUIC 用原生流，TCP 用 yamux；单连接上限 64 流 |
| 帧（frame） | 流语义层最小封装：无符号 varint 长度前缀 + 定长 payload，单帧上限 1 MiB |
| varint | LEB128 无符号变长整数：每字节低 7 位承载数据，最高位为后续标志；最多 10 字节 |
| 协议 ID | 流的路由键：`/段/段/数字版本`，如 `/p2p-base/rendezvous/1`；每条流只承载一个协议 |
| 开流握手 | 新流首帧 = 协议 ID 的 UTF-8 字节（帧封装）；收端查注册表分发，未注册即关流报错 |
| handler | 节点内某协议 ID 的入站处理回调；处理完该流即返回（返回即关流） |
| request-response | 一问一答原语：开流、写协议 ID、写请求帧、读一帧回应、关流；单个超时覆盖全程 |
| chunked | 大消息分帧：帧 payload 首字节为类型头 0x00/0x01/0x02（单帧/中间片/末片） |
| mDNS | 局域网发现：服务类型 `_p2pbase._udp.local.`，TXT 携带 PeerId 与端口 |
| rendezvous | 跨网发现：节点向引导节点签名注册地址，其他节点按 PeerId 查询 |
| relay（中继） | 公网节点代为桥接两条已认证连接之间的密文字节流，无法解密业务数据 |
| 打洞（punch） | 借中继交换信令后双方同时向对方地址发包，尝试建立直连（类 DCUtR） |
| hairpin | 同 NAT 回环：对端地址与自身观测地址同公网前缀，多数 NAT 不支持直连回环 |
| 降级链 | 拨号顺序：直连逐地址尝试，失败转打洞，再失败接中继电路；每跳发事件 |
| 电路（circuit） | 中继上的逻辑链路标识（u64）；预留后对端凭 Connect 接入即配对桥接 |
| ALPN | QUIC 握手的应用层协议协商，本栈固定 `p2p-base/1`，不匹配即握手失败 |
| Noise XX | TCP 路径安全握手：`Noise_XX_25519_ChaChaPoly_SHA256`，无明文阶段 |

## 5. 兼容性承诺摘要（v1）

实现以下六条即可长期兼容本栈（详见 [builtin-and-versioning.md](builtin-and-versioning.md) 第 4 节）：

1. 帧封装无版本字段，语义完全由流首帧的协议 ID 决定；帧格式本身保持稳定。
2. 控制面 protobuf 只新增字段/变体，不改已有 tag 与类型；未知字段按 protobuf 语义跳过。
3. 不兼容变更升协议 ID 版本号（`/x/y/1` 变 `/x/y/2`），新旧并存路由；禁止原地改语义。
4. 未知协议显式失败：收端关流并上抛 UnsupportedProtocol，不做猜测降级。
5. 控制面新枚举变体发给旧端时，旧端按协议违规回 Reject(code=4) 并断流，失败可见。
6. 传输层演进走 ALPN（`p2p-base/1`）与 Noise 域串（`p2p-noise-xx-v1`）的版本段，
   不匹配在握手期即失败，不产生半兼容连接。

PeerId 公式经裁决定稿为对原始公钥直接取 SHA-256（不同于 libp2p 的 multihash 封装）；
与其他体系的互操作如需调整，以新版本号演进，不改 v1 语义。

# /repair/mcp/1 规范

状态：stable；自 2026-09-03；归属 crates/repair-bridge；符合性：Core = stdio 双向
哑泵、帧边界与 EOF 退出语义；Extended = 无。

## 1. 概览

远程支持场景的 MCP stdio 字节隧道。桥进程（repair-bridge，运行在受助节点）把本机
MCP 客户端（runner）的 stdio 与指向 helper 节点的一条 p2p-base 逻辑流双向对拷；
helper 节点把流还原为 MCP server 的 stdio 供宿主面消费。泵是哑的：不解析、不改写、
不缓存任何字节，帧边界只是底座单帧上限约束下的字节分块，不构成消息边界。

适用边界：

- MCP 语义（JSON-RPC、工具调用、审批）不属于本协议；协议两端看到的就是原始
  字节流，任何一端挂非 MCP 字节本协议同样照搬。
- 票据前置帧是流上承载的接入约定（§2.2），其载荷语义与校验属 helper 上层（§5.2）。
- 帧封装（varint 长度前缀、单帧 1 MiB 上限、超限断流）复用底座，见
  docs/protocol/wire-format.md；本文只写帧序列与承载语义。

## 2. 线格式

### 2.1 帧序列

| 序 | 载荷 | 方向 | 语义 |
|---|---|---|---|
| 1 | 协议 ID `/repair/mcp/1` 的 UTF-8 字节（底座标准开手） | 桥→helper | 路由到本协议 handler |
| 2 | 票据字节（恰一帧，UTF-8 文本） | 桥→helper | 接入凭证前置帧，见 §2.2 |
| 3 起 | MCP 字节流分块 | 双向 | 字节透传：无类型头、无序号、无确认、无消息语义 |

### 2.2 票据前置帧

- 桥必须在任何 MCP 字节之前先写票据帧并 flush；票据恰为一帧，字节数必须
  ≤ 1 048 576（底座帧上限）。
- 票据内容为平台铸造的凭证文本（base64url 载荷 + "." + base64url 签名形状）；
  其载荷字段、验签公钥、时效、一次性与对端绑定均属 helper 上层契约（§5.2）。
  本协议对其内容零解释，仅承载字节。
- helper 必须先完整读取首业务帧并完成上层校验，通过后才进入字节泵；校验失败
  即拒绝受理（§4），不得有任何 MCP 字节进入宿主。

### 2.3 分块规则

- 桥→helper（stdin 方向）：从 runner stdin 读取字节，每次读到的实际字节即为一帧
  载荷（单次读长上限 1 048 576 字节），逐帧写出后立即 flush；读到 EOF（0 字节）
  时必须对该方向执行写半关（shutdown），本方向正常收尾。
- helper→桥（stdout 方向）：宿主写侧字节按 65 536 字节读块，再按底座帧上限
  （1 048 576 字节）切帧写回，写后立即 flush。
- 两方向完全独立、并发对拷；背压由逐帧写出与底座流背压承担，任何方向不得缓冲
  无界增长。

## 3. 时序与状态机

### 3.1 桥侧（受助节点）

```
解析参数（helper peer / 票据 / bootstrap 地址）
  → 组网并等待发现 helper（发现超时 30 秒即失败退出并留日志）
  → 连接 helper，开流写协议 ID
  → 写票据帧（§2.2）
  → 启动两个独立方向任务，进入哑泵直至 §3.2 退出条件
```

票据参数可以是票据文件路径（存在则读文件内容）或票据文本本身；解析属桥装配层，
不入线格式。

### 3.2 EOF 退出语义（核心）

- 方向任务只有两种结束方式：
  - stdin 方向：runner 侧 EOF = 正常收尾（写半关后本方向成功返回）；
  - stdout 方向：帧流终止（对端断流、帧读错误或写侧失败）= 方向失败，留日志。
- 整泵语义：任一方向任务结束，另一方向必须立即中止，整条隧道必须终止——不允许
  半开连接滞留。结束原因必须可观测：整泵一律以 UnexpectedEof（"bridge direction
  closed"）收尾并留错误日志，进程以非零码退出（实现恒为 1，含 stdin EOF 的正常
  收尾路径——EOF 即停止服务是该工具的既有约定）。
- helper 侧对称：帧→字节与字节→帧两个泵任务任一终止（含流断、写失败），整条
  受理必须立即结束，宿主读侧随写半关收到 EOF 自然收尾；挂起中的工具审批无人
  应答按上层超时规则处理（60 秒超时即拒，断线视同拒绝，无放行路径）。

### 3.3 非法情形

- 以未注册协议 ID 开流：底座关流上抛 UnsupportedProtocol（底座行为，见
  docs/protocol/builtin-and-versioning.md §3.1），不产生本协议层交互。
- 首业务帧缺失（流提前关闭）或票据帧非 UTF-8：helper 拒绝受理并断流。
- 单帧超 1 048 576 字节或 varint 长度前缀非法：底座帧层报错断流（FrameTooLarge /
  varint overflow 语义），本协议不定义额外处理。

## 4. 错误语义

本协议没有协议级错误码或错误帧：哑泵不产生任何带外信令，一切失败都表现为
流终止加端侧可观测信号（日志/退出码/审计由上层负责）。

| 失败 | 检出方 | 确切行为 |
|---|---|---|
| 票据校验不过（签名/过期/scope 枚举外/对端不符/一次性已用） | helper 上层 | 拒绝受理：warn 日志含原因与 peer，立即关流；桥只见流关闭 |
| 连接门禁未观测到入站 peer | helper | 拒绝受理并断流（无对端归属即拒绝） |
| 票据帧缺失或非 UTF-8 | helper | 拒绝受理并断流 |
| runner stdin EOF | 桥 | 写半关，本方向成功收尾；整泵随之终止（§3.2） |
| 对端断流 / 帧读错误 / 写侧失败 | 双方 | 方向失败留日志；整条隧道终止 |
| 底座帧层违例（超限/varint） | 双方 | 底座断流语义（builtin-and-versioning §3.1） |

## 5. 安全考量

### 5.1 传输与认证边界

- 机密性与对端认证完全由底座承担（QUIC TLS1.3 证书内嵌公钥 / Noise XX 握手互认，
  见 docs/design/wire-protocol.md §5/§6）；本协议不另设鉴权，也不得采信载荷内
  自报身份。
- 单帧上限 1 048 576 是协议内唯一资源护栏；无心跳、无限速、无并发上限，连接面
  由底座每 Peer 限制与上层受理门禁约束。

### 5.2 本协议与上层的边界声明（按代码为准）

以下属于 helper 上层（crates/repair-helper、crates/repair-enforce），不属于本协议，
但依赖本协议的字节承载：

- 票据契约：载荷字段（ticket_id / helper_peer / bridge_peer / scope / iat / exp）、
  ed25519 验签（平台公钥注入）、exp 过期否决、scope 枚举（diag/fix）、工单一次性
  台账查重——全部在 helper 侧校验，通过前不得有任何 MCP 字节进入宿主。
- 未知对端拒绝：helper 依赖底座连接门禁在连接建立期捕获入站 PeerId，与票据
  bridge_peer 比对，不一致即拒（单桥部署的最近观测口径）；比对与拒绝裁决属
  上层，本协议只如实上送流与首帧字节。
- 审计与执法：MCP 工具注册表、路径监狱、shell 白名单、审批状态机、会话报告与
  审计留痕均为上层执法面；本协议无法区分合法与恶意字节，也不承载任何执法语义。

第三方实现本协议时必须保持该边界：只实现 §2/§3 的字节承载与 EOF 语义，不得把
票据校验或执法逻辑下沉进泵；票据与执法规则变更不应引起本协议升版。

## 6. 兼容与版本

- 无握手帧、无版本字段、无能力协商：流语义完全由协议 ID 决定；演进 = 升协议
  ID 版本（/repair/mcp/2 新建规范页），新旧 ID 并存路由一个过渡期，禁止原地改义。
- 字节透传对 MCP 版本零假设；runner 与 helper 宿主之间的 MCP 能力协商走透传
  字节自身，与本协议无关。
- 票据前置帧是 v1 流上约定：未来若前置帧语义需要不兼容变更（如加密票据、双向
  握手），必须升协议 ID 版本。
- 探测：开流写本协议 ID，未注册对端关流（UnsupportedProtocol）即不支持。

## 7. 测试向量

无。首波向量集清单（spec-charter §8）未含本协议：帧封装字节语义由章程 §8 冻结
清单中的 frame.json 覆盖（向量文件随后续轮落地，本协议直接复用，不重复登记）；
哑泵行为由 crates/repair-bridge 单元测试（EOF 退出、大载荷分帧保序、原样透传）
与 crates/p2p-itest 回环用例覆盖；票据黄金字节列为后续向量集候选。

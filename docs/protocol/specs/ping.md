# /p2p-base/ping/1 规范

状态：stable；自 2026-09-01；归属 crates/p2p-swarm；符合性：Core 项=全部章节（探活属互通必需行为契约）

## 1. 概览

- 解决什么问题：判定一条已建连接是否存活并测量往返延迟（RTT），兼作应用层保活。
- 选型契约：探活必须走协议层 ping，不得只依赖传输层 keepalive。理由：QUIC keepalive
  只覆盖 QUIC 直连，TCP 与中继电路路径探测不到；传输层活性也无法发现对端进程挂起
  （半死连接）。协议 ping 在复用层流上往返，QUIC/TCP/中继电路三种路径语义一致，
  且端到端验证对端协议栈确实在服务。
- 自动注入：节点组装 handler 注册表时必须自动注入内置 ping 应答器；用户同名注册
  优先，注入器不得覆盖已有同名 handler（测试可据此模拟失聪对端）。
- 保活用法（参考实现节奏）：对在册连接每 10s 探测一次、单次探测超时 3s；连续失败
  判定连接死亡并发下线事件（node-lifecycle.md §3.1）。

## 2. 线格式

流首帧 = 协议 ID 帧；其后每帧一个业务 payload，无类型头、无版本字段。

- 首帧 payload：`/p2p-base/ping/1` 的 UTF-8 字节，16 字节；完整首帧 17 字节
  （wire-format.md §11 例 A，已验证）：

      10 2f 70 32 70 2d 62 61 73 65 2f 70 69 6e 67 2f 31

- 请求帧：payload 为任意字节，长度必须满足 0 <= len <= 1 048 576（MAX_FRAME_SIZE）。
- 应答帧：payload 必须与请求帧逐字节相同（原样回声）。
- 发送方请求内容实现可以任选（本仓用 8 字节墙钟纳秒小端编码作 nonce）；内容仅用于
  回声比对，协议对其不赋予任何语义。

## 3. 时序与状态机

发起方（探测者）：

    开流 -> 写协议 ID 首帧 -> 写 1 个请求帧 -> 读 1 个回应帧 -> 逐字节比对 -> 关流

全程受一个超时约束（参考值 3s），任一环节卡住即探测失败，不悬挂。

应答方（被探测者）：

    流进入 handler（已剥协议 ID 首帧）-> 读 1 帧 -> 原样回 1 帧 -> handler 返回（关流）

状态机：无状态；每条流恰好一问一答。约束：

- 应答方读完第一帧即返回，后续到达的帧不承诺处理——请求方不得在收到回应前发送
  第二帧，不得假设多帧会话。
- 空 payload 帧（长度 0）语法合法，应答方必须原样回一个空帧。
- 应答方不得抢占用户 handler：注册表已有同名 handler 时不注入。

## 4. 错误语义

| 信号 | 触发 | 收发双方确切行为 |
|---|---|---|
| FrameTooLarge | 帧长超 1 048 576 | 断流；写侧不写出任何字节（wire-format.md §6） |
| 回声不一致 | 回应帧与请求帧不等 | 发起方判探测失败（非致命），连接保留，继续按节奏重探 |
| 超时 | 全程超过探测超时 | 发起方判探测失败（非致命） |
| EOF/BrokenPipe/ConnectionReset/NotConnected | 对端关流或链路已死 | 发起方判连接层死亡，立即结束等待，不必等满未命中窗口 |
| UnsupportedProtocol（流被立即关闭） | 对端未实现本协议 | 发起方必须停止对该连接的协议层探活，按连接策略处理，不猜测降级 |

探测失败的处置由上层策略决定（参考实现：连续失败判连接死亡）；本协议层不定义
「连续」阈值。

## 5. 安全考量

- 不新增认证面：传输握手已完成 PeerId 互认，ping 不承载身份语义。
- nonce 不得用于安全用途：参考实现取墙钟纳秒，可预测；ping 往返不得当作对端身份、
  抗重放或抗中间人的证据。
- 反射放大面：应答长度 <= 请求长度，无放大收益，第三方实现不得引入放大行为。
- 滥用面：高频探测消耗流额度与 CPU。天然约束：单连接双向流上限 64、空闲连接回收
  120s、对端可以不实现（关流）。实现应当允许对 ping 频率设上限。
- 探测结果外泄面：RTT 可被同连接上的业务流量间接观察，协议本身不增加新泄露。

## 6. 兼容与版本

- 应答语义是逐字节回声，因此载荷可以加法演进：新端发结构化载荷，旧端原样回传仍是
  合法应答；新端若解析回传失败，必须降级为纯回声比对，不得判定对端不兼容。
- 本协议 ID 语义冻结（stable）：只允许加法；不兼容变更必须升版为 `/p2p-base/ping/2`，
  新旧 ID 并存过渡，禁止原地改义。
- 探测方式：无预协商，以「开流写协议 ID → 被立即关流」判定对端不支持。

## 7. 测试向量

按 spec-charter.md §8 首波清单，本协议无专属向量集（registry 中 vectors 为空）。
适用通用向量文件（由向量轮并行交付，落地前按文件名引用，不另造向量）：

- `vectors/frame.json`：帧封装往返、1 MiB 上限、长度不符断流；
- `vectors/varint.json`：长度前缀 varint 边界值与溢出拒绝；
- 本文 §2 给出的协议 ID 首帧 17 字节即本协议的字节级锚点，与 `vectors/frame.json`
  的帧封装规则联用。
